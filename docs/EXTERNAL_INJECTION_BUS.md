# ExternalInjectionBus — Universal External Data Hub

> Single exit/entry point for data injected by EXTERNAL features (addons +
> external cortex modules) into Yui's awareness. Used by BOTH the main prompt
> and sub-agent delegation, so delegated agents sense the same world Yui does.
>
> Related docs: addon ↔ cortex module pairing → `docs/ADDON_CORTEX_INTEGRATION.md`;
> external cortex modules → `docs/CORTEX_MODULES_EXTERNAL.md`.

## 1. What it is

`src/core/kernel/externalInjectionBus.ts` is a manifest-driven hub. External
features live OUTSIDE the codebase and must not require code changes to
participate. The bus collects every source and renders one complete snapshot
("jala keluar-masuk data lengkap") for any consumer:

- the **main prompt** (via `PromptManager`)
- **sub-agent delegation** (via `SubAgentManager`)

Nothing in the bus is feature-specific — every source is declared through
manifests, so **any** addon can join without touching daemon source.

## 2. Data sources

| Source | Location | How it's discovered |
|---|---|---|
| Addon state files | `~/.yuihime/addons/<id>/inject.json` | Manifest lists one or more `sources`, each pointing to a state file |
| External cortex module inventory | `~/.yuihime/cortexloader/<id>.json` | Every JSON (except `registry.json`) is listed as an installed module |
| Live per-turn injections | `context.externalInjection` | String set by cortex modules (e.g. vbody inject) during the pipeline |
| Grounded knowledge | `context.groundedKnowledge` | Existing field, passed through as-is |

The manifest cache is lazily refreshed every **15 s** — dropping a new
`inject.json` or module into the folders is picked up **without a rebuild or
daemon restart**.

### inject.json manifest format

```json
{
  "sources": [
    {
      "id": "my_feature",
      "label": "My Feature State",
      "file": "my_feature.json",
      "maxChar": 3000
    }
  ]
}
```

- `file` is resolved relative to `~/.yuihime/user_data/` (or absolute).
- `maxChar` truncates very large files before they reach the prompt.

## 3. Consumers

### Main prompt (`PromptManager`)

Rendered inside `<external_feature_injections>`:

- file blocks (`[LABEL]\n<content>`), one per manifest source
- `[INSTALLED EXTERNAL CORTEX MODULES]` inventory
- the unified spatial-awareness block (see below)

### Sub-agent delegation (`SubAgentManager`)

`ExternalInjectionBus.renderSubAgentBlock()` renders the same snapshot into the
sub-agent prompt as `[EXTERNAL FEATURE INJECTIONS]`, so a delegated research /
creative / explorer agent knows exactly what Yui knows about her body, her
outfit, her location and who is with her.

## 4. Spatial awareness — the "room = current place" mapping

`src/core/kernel/situationalContext.ts` provides shared helpers used by both
consumers, so spatial-temporal awareness stays consistent everywhere:

| Helper | Purpose |
|---|---|
| `computeRoomOccupants(memories, context)` | Distinct speakers (not agent/system rows) active within a **2 h** proximity window, capped at 5, newest-first. The person being replied to is ALWAYS included and marked `YOU ARE CURRENTLY TALKING TO THIS PERSON`. |
| `buildSpatialAwarenessBlock(...)` | Single spatial-truth block: `WHERE YOU ARE AND WHO IS WITH YOU`. States that the room and the current place are the SAME place (at home: rumah = ruangan; when out: wherever she is is her room). Explicitly forbids "alone / berdua aja / nobody else" answers while names are listed, and says a name disappears only after 2 h of silence. |
| `buildSpatialHint(...)` | Ultra-compact fact placed at the TOP of the assembled system prompt so even weak models latch onto it (e.g. "3 of you together — answer 3"). |
| `buildRecentDialogueTranscript(...)` | Chronological transcript, each line prefixed with absolute local wall-clock time. |

### Dynamic location

`ExternalInjectionBus.resolveCurrentLocation()` resolves where Yui is right now
from the **manifest-driven state files** (reads the first generic JSON `location`
field). No feature-specific marker or tool name is hardcoded — any addon that
publishes a `location` field can drive it. This makes Yui's location:

- **cross-channel consistent** — a move from CLI is answered correctly on TG;
- **dynamic** — when a user invites her to another place, she moves there and the
  updated location is picked up on every subsequent turn from any channel.

## 5. Rules / constraints

- **Never hardcode a feature** (vbody or otherwise) in the bus, situational
  context helpers, or prompt templates. Everything must flow through manifests.
- The current user must never be counted as absent, even if their last stored
  message is older than the 2 h window (they are talking right now).
- All AI-facing text generated by these helpers is English.
